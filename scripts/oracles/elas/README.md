# Local libELAS comparison oracle

`build.sh` fetches the one-commit [unofficial mirror](https://github.com/kou1okada/libelas) of Andreas Geiger's libELAS into ignored `.local-tools/oracles/elas/upstream`, verifies commit `862ee4ef30a070753e9b92965855562a4482da05` and SHA-256 `ae32ab63888994910e6813b65242a8f05ffc86e448048d6fe67dcd1eb4830a8d` of `git archive --format=tar HEAD`, then builds a separate x86_64 test executable with Apple's Clang (`-msse3 -O2 -Wno-c++11-narrowing`). The last flag permits an upstream integer-to-float brace initializer; no algorithm code is changed. It runs locally through Rosetta on Apple Silicon. No global package is installed, and no oracle source is linked into CrispMesh. The adapter uses the upstream `MIDDLEBURY` preset, with disparity minimum 0, inclusive maximum `ndisp-1`, and full-resolution output. It converts ELAS invalid values to Middlebury `+INF` PFM.

The libELAS files say GPL-3.0-or-later. Its bundled, modified `src/triangle.cpp` is Jonathan Shewchuk's Triangle 1.6 and has separate terms: private, research, and institutional use is free; redistribution requires notices and no compensation; distribution as part of a commercial system requires direct arrangement with the author. This local research comparison makes no distribution decision. See the full upstream file header and the [author's libELAS page](https://www.cvlibs.net/software/libelas/).

Input contract: `elas_oracle --left prepared/left.pgm --right prepared/right.pgm --ndisp COUNT --output disparity.pfm`. `COUNT` is a GT-independent search count from `inputs.json`; both PGM files are byte-identical inputs across oracles. The wrapper reads no ground truth. Score its PFM with `crispmesh_stereo_eval --prediction disparity.pfm --gt prepared/truth.pfm --output-dir score-dir`.
