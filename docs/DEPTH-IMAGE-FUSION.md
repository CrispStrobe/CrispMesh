# Image-derived depth to track fusion experiment

`depth_image_fusion_synthetic` connects rendered image matches to `fuse_tracks` on a 450 mm foreground patch in front of a 500 mm panel. This is a two-depth surface with a step and occlusion, not a general curved surface. Three cameras are at distinct centers and have a common 0.025 rad yaw, so rectified points require both inverse rectification and inverse first-camera pose to reach the object frame. Analytic transform assertions check this chain for cameras a and b, including nonzero translation for b. Known geometry supplies the rendered images and the final scoring truth only; it does not set candidate positions, confidence, support depths, or acceptance gates.

The a–c pair supplies the raw candidate for each sampled reference pixel. Separate a–b and b–c matches supply axial depth maps in camera a and camera b, respectively. The pair maps share some source images and are therefore correlated; only the b–c support map has a different first-camera center from the a–c candidate map. Each reference pixel is a track ID. Two arms use the same gates and scoring grid: a one-candidate a–c control measures cross-view filtering, and a two-candidate a–c plus a–b arm exercises confidence-weighted track averaging with equal confidence. An a–b candidate is correlated with its own camera-a support depth, so this is a wiring experiment rather than three independent observations.

Before SGBM, rectified object masks are eroded three pixels and all pixels outside them are set to zero. Forward and reverse disparities must each fall in their configured search intervals and agree within 1.5 pixels. The test changes all exterior source pixels, repeats all three pair matches, and asserts identical disparities and valid masks. This establishes an outside-mask mutation invariant for the fixture. It does not make SGBM's global path costs independent of masked boundaries or remove occlusion effects inside the object mask.

Settings fixed before the first control run: 640×480 images, focal length 800 px, 40/70 mm second/third camera centers, 400–560 mm disparity search, 5 px SGBM block, every third pixel on the full rectified foreground grid, 8 mm cross-view/fusion tolerance, and 100 mm error assigned to every missing estimate for fixed-population scoring. The two-candidate arm was added after the control's first run, with the same settings and equal candidate confidence declared before its first run. There is no scoring crop: the grid includes the matcher search strip and object boundaries. The 2 mm bad-pixel count includes missing estimates. Report fields include completeness, observed-only p95, and fixed-population mean/p95 and bad2 counts for the whole object, each surface, and the depth-step boundary. The acceptance test requires a minimum population and output count; it does not assert that fusion improves image quality.

The first control run (2026-09-26) had 9,519 foreground samples, 8,833 raw a–c estimates (92.8% complete), and 8,790 filtered outputs (92.3%). Fixed-population bad-or-missing >2 mm counts rose from 813 to 827 overall and from 206 to 215 among 1,098 boundary samples. The observed-only boundary p95 fell from 3.23 to 1.93 mm; this reflects removal of difficult points, while full-grid coverage and quality became slightly worse.

The first two-candidate run on the same fixture produced 8,822 outputs (92.7%). Fixed bad-or-missing >2 mm counts rose from the same raw baseline of 813 to 854 overall and from 206 to 232 at the boundary. Observed-only boundary p95 rose from 3.23 to 3.89 mm. The foreground fixed-population mean improved from 2.805 to 2.372 mm, but its bad-or-missing >2 mm count rose from 40 to 50. Neither arm shows an aggregate quality gain. Whole-object and boundary fixed-population p95 is 100 mm because more than 5% of samples lack output. The JSON report sets `ok: true` for the passing wiring regression, `twoCandidateQualityGatePassed: false` because the two-candidate arm improves neither whole-object nor boundary missing-inclusive bad2, and `productionAccepted: false` because this synthetic fixture is not a production acceptance test. It also reports separate whole-object and boundary improvement booleans for each arm. The filter-only control does not enter the two-candidate quality gate: removing an estimate cannot improve a bad-or-missing count.

Build and run using the existing OpenCV build:

```sh
cmake --build build-opencv --target crispmesh_depth_image_fusion_tests -j 4
TMPDIR=.local-tools/tmp ctest --test-dir build-opencv -R '^depth_image_fusion_synthetic$' --output-on-failure
```

Each run writes masked images, a candidate-valid mask, a control-arm accepted mask, two depth-view support masks, and `report.json` with both arms under `build-opencv/depth-image-fusion-fixtures/run-*`. The test reserves at least 10 GiB of free space before writing. It is a synthetic regression only; it does not enable product reconstruction or demonstrate accuracy on photographs.
