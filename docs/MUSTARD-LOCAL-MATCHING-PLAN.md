# Frozen mustard local-graph mapper comparison

This is one image-only, train-only **graph-restriction** experiment, frozen before its run. The original masked fixed-initial exhaustive SfM remains sealed and untouched; the new mapper reads a fresh copied COLMAP database, never the source database in write mode. No images, SIFT descriptors, matches, intrinsics, initial pair, pose priors, masks, held-out frames, Berkeley sensor data, or Google shape-reference geometry are added. It stops after sparse SfM; no dense reconstruction or mesh/reference score is authorized by this plan.

This is *not* a 24-degree nominal-angle cutoff; held-out gaps can make the corresponding acquisition-angle separation larger. It is not a camera pose prior or manual seed. The restricted nonempty verified graph has **one component of 48 and no isolated image**. These numbers are preflight assertions, not target reconstruction outcomes. The original exhaustive graph has 420 nonempty raw-match pairs and 400 nonempty verified pairs. No new correspondence computation is allowed.

## Fixed mapper and diagnostics

Run the same pinned PyCOLMAP 3.11.1 CPU mapper on the copied DB and same 48 TRAIN images/masks, using the source's effective `fixed-initial` SINGLE SIMPLE_RADIAL camera `[1536,640,512,0]`, seed `20260927`, model retry maximum 5/minimum model size 10, and 70% registration producer gate. SIFT is **not rerun**; it is exactly the source DB's 1,800-feature/1,200-pixel extraction and matching population. The only intended input difference is the restricted verified-pair graph. No supplied camera pose, manual initial image pair, delayed intrinsics refinement, or feature/mask adjustment is allowed. Record the mapper's actual initial pair and options, plus source and copied DB/model/runner hashes, before and after stage. The old exhaustive run's initial pair was image IDs 3/6 (`NP3_012.jpg`/`NP3_036.jpg`), itself within the local-four graph; therefore a changed outcome cannot automatically be attributed to removal of a nonlocal initial pair.

Assess both runs on the *same 48 training names* using registered count and missing names, selected model count, camera intrinsics, points, observations, distinct-view track lengths, duplicate-image tracks, finite reprojection residual mean/median/p95 with observation denominators, and actual pair/verified-correspondence populations. **Registration count alone is not acceptance.** Report scale-invariant camera-trajectory fold diagnostics: center positions ordered by the frozen training-name cycle; adjacent-step distances (including wrap) and their spread, nonlocal-center alias distances relative to median adjacent distance, center-plane fitted angular winding/step reversals, and relative orientation changes against acquisition ordering. The angle labels are diagnostics only, not a reconstruction seed or physical GT. Report poor/degenerate plane fits as unavailable rather than inventing a clean orbit. Inspect initial-pair and registration logs for global aliasing; the exhaustive initial pair being local makes a simple “bad long-range seed” explanation unsupported. The source DB's saved verified-pair `qvec`/`tvec` values are identity/zero placeholders, so they are **not** an independent pair-pose accuracy measure. Do not pick a preferred model by Google mesh fit or after seeing dense scores.

Use the approved experiment limits: fresh external output, two CPU threads, 4 GiB sampled child RSS, **512 MiB output**, 32 MiB stage logs, 10 minutes, and at least 10 GiB free on internal and external volumes. Preserve failures and partial models with explicit status; no automatic retry or option search. Any later dense continuation or independent evaluation requires a separately frozen quality gate and approval.
