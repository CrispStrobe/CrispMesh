The code [README](https://github.com/facebookresearch/map-anything/blob/3d10cf7a3016fc0f9bb13a071ee66c47b10be0d9/README.md) explicitly distinguishes its Apache model from a CC-BY-NC variant and supports image-only inference with predicted intrinsics and OpenCV-convention camera-to-world poses. Some README examples still instantiate the **non-commercial default ID**; this experiment must name `facebook/map-anything-apache` explicitly. “Metric” in the model description is a prediction claim, not a calibration certificate for our rotating-object photographs. Its stated 2,000-view memory-efficient example uses a **140 GB GPU**; it does not establish a 16 GB T4, Mac, or iPhone memory budget. The 4.91 GB file size excludes activations, image tensors, framework, and GPU allocator. OOM is an acceptable feasibility outcome, not a reason to silently reduce the frozen input or switch weights.

## Frozen first experiment (not yet executed)

1. Input only existing original YCB cracker-box training photos `NP3_000.jpg`, `NP3_006.jpg`, `NP3_012.jpg`, in that order, with the exact source bytes rehashed and logged. These are three **nearby turntable angles**, so camera baselines may be too small for a stable similarity fit; this is a small-input API/memory/pose diagnostic, not coverage or quality evaluation. No Google scanner mesh, Berkeley depth, supplied turntable poses/angles, existing COLMAP cameras, or held-out images enter inference. No downloaded dataset or mask is substituted. The angle labels here only identify the fixed filenames, not model inputs.
2. Load the **locked Apache weight revision** with pinned code, image-only inference, fixed original inputs, and a declared resize/pixel-orientation policy before execution. Record device/GPU, framework and dependency versions, output pose convention, image preprocessing, wall time, peak allocated/reserved GPU memory, and failure status. Do not treat the README's memory profile as a local measurement. First independently check projections and pose matrix validity.
3. Compare predictions *after inference* to the already saved named-image COLMAP estimate using relative rotations and translation geometry; if a proper Sim(3) camera-center fit is well-conditioned, disclose its singular values, scale, residuals, and the fact that COLMAP is a software comparator, **not ground truth**. Never choose image selection, alignment, resize, or checkpoint by the comparison score. The saved COLMAP model may itself have used additional photographs, so this is **not** an end-to-end held-out quality comparison. Do not claim metric scale or scanner-reference agreement from this test.
